# 第三问 v3（Claude）：高精度新数据上的正式求解

> 数据用 PR #22 合并进来的高精度版 `data/数据.xlsx`。方法与 v2 相同（`docs/q3/v2_第三问_claude.md`），区别是换了数据，并把 δa 的扫描加密到 0–25 km。v1、v2 的文件都保留不动。

## 结果

两颗星合计观测 30 颗目标，总 Δv 为 **35.850 m/s**：r1 负责西侧 10 颗，用 18.943 m/s；r2 负责东侧 20 颗，用 16.907 m/s。两颗星的方案都经 `tools/verify_p2.py` 按题面约束严格复核通过，分别为 10/10 和 20/20。单次脉冲最大 3.41 m/s，脉冲间隔都不小于 3600 s。

r2 的初始轨道参数是：半长轴 a = a_GEO + 7.76 km，偏心率 e = 0.00016，倾角 i = 4.379°，升交点赤经 Ω = 76.97°，与 r1 共面，起点在 r1 以东 4°。具体做法是先按 Δa = +3 km 的圆轨道求解，再把 t = 0 时 0.384 m/s 的首脉冲并入初始速度，所以这次脉冲不计入 Δv。这个设计要求 δa ≥ 7.77 km。

## 换数据带来的变化

新数据修正了 b3、b5、b9、b15 四颗目标的初始状态，r1 和其余目标只有舍入级的差别。变化最大的是 b9：它的半长轴原来比 GEO 低 40.5 km，现在回到了 GEO 附近。在旧数据下，b9 自身有较快的相对漂移，r1 可以"顺路"观测到它；现在这个便利没有了，所以 r1 的消耗从 16.547 增加到 18.943 m/s，观测顺序中 b9 也排到了 b8 之后。r2 侧的消耗从 17.716 降到 16.907 m/s，最优的初始半长轴偏置也从 +15 km 降到了 +3 km 左右。

我们也试了另外两种分组：把 b2 交给 r2，或者把 b4 交给 r1。两种情况的总 Δv 都明显更高（r1 侧分别为 21.6 和 28.2 m/s，r2 侧拿到 b2 之后超过 50 m/s），所以仍以 r1 的位置为界划分东西两组。

## δa 的参数分析

给定 δa 后，r2 的初始半长轴必须落在 [a_GEO − δa, a_GEO + δa] 内；如果把首脉冲并入初始轨道，并入后的半长轴也要满足这个条件，同时 e < 0.001。下表对每个 δa 取所有已扫描设计中的最优值。扫描范围是 Δa ∈ {0, 2, 3, 5, 7, 10, 12, 15, 18, 20, 25} km，起点 ∈ {2, 3, 3.5, 4, 4.5, 5}°，r2 与 r1 共面。

| δa (km) | r2 最优 Δv (m/s) | 两星合计 (m/s) | 对应设计 |
|---|---|---|---|
| 0 | 17.439 | 36.382 | 初始 a = a_GEO，起点 +4° |
| 2 | 17.356 | 36.299 | Δa = +2 km，起点 +4° |
| 3 | 17.291 | 36.234 | Δa = +3 km，起点 +4° |
| 5 | 17.243 | 36.186 | Δa = +5 km，起点 +4° |
| 6.3 | 16.931 | 35.874 | Δa = 0，首脉冲并入后 a − a_GEO = 6.29 km |
| **≥ 7.8** | **16.907** | **35.850** | Δa = +3 km，首脉冲并入后 a − a_GEO = 7.76 km（本版采用） |

可以看出 J*(δa) 随 δa 单调不增，但整条曲线非常平：δa 从 0 放宽到 7.8 km，总 Δv 只下降 0.53 m/s（1.5%）；超过 7.8 km 之后，在已扫描的设计范围内不再下降。也就是说，在新数据下，第三问的结果对 δa 很不敏感。即使 δa = 0（r2 恰好位于 GEO 半长轴上），方案也只比最优多 0.53 m/s。论文中可以把 δa = 8 km 作为推荐值，并用这张表说明 δa 对结果的影响很小。v1 文档里"δa 超过约 55 km 后不再增加观测能力"的上界论证仍然成立，只是在新数据下，曲线远在达到这个上界之前就已经饱和了。
